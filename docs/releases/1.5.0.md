# Botty+ 1.5.0 — Background services in rest mode

Botty service 1.5.0 renews the PS5 system keep-main request every ten seconds
while the manager runs, including after closing Botty+. This replaces the
ten-minute experimental payload with maintenance tied to the service lifetime.
The feature is enabled on the portal's supported firmware range, 7.00–13.60.
Runtime lookup and request failure leave Botty usable and expose the failure
in the API and web footer. Requests are renewed independently of torrent and
file-operation locks. Stopping the service stops renewals.

On firmware 13.00, user-confirmed rest-mode trials kept FTP, rTorrent and Botty
available. A private generated 8 MiB torrent downloaded in standby and its full
FTP readback matched SHA-256. Both original torrents were retained, and Botty
was Online after wake. Upload, extraction, compression, longer rest periods,
power consumption and other firmwares have not been validated on hardware.
Maintaining the main processor in standby may use more power than deep rest.

The native app remains 01.004.000; rTorrent, ShadowMountPlus, Kstuff and the
optional PPR payload retain their versions. The portal stages service updates
without interrupting a running older service. Use LAUNCH from a fresh console
session to activate 1.5.0 after updating the portal. No game files, saves,
archives or torrent configuration are replaced by this feature.

Validation: host lease/expiry/firmware/stop regressions, service integration
tests, portal upgrade tests, release export/source tests, VPS PS5 build and
verified public package hashes/installer pins. On firmware 13.00, the final
service was installed with rollback and seven raw-mode transfer/hash receipts.
Runtime API lookup and repeated renewals passed: maintenance was still active
130 seconds after activation, and both original torrents remained available.
The standby download/readback evidence comes from the underlying prototype
trials; long production standby sessions remain pending.
