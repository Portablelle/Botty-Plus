# Botty+ 1.5.1 — Restore native app connectivity

Botty+ could show Offline with service 1.5.0 even when rTorrent and the manager
were responding. The new nested rest-mode object in `/health` violated the
installed native app’s flat API v1 parser. Service 1.5.1 restores the original
four health fields. Rest-mode details remain in authenticated `/api/rest-mode`
and `/api/state.restMode`; maintenance stays enabled on firmware 7.00–13.60.

The native app remains 01.004.000. No game files, saves, archives or torrent
settings are changed. The portal recognizes 1.5.0 and stages the update without
interrupting existing work.

Validation includes the real native probe-to-catalog flow against the host
service, a flat health contract regression, portal upgrade tests, public package
checks and a PS5 build on the VPS. Standby validation remains the firmware 13.00
prototype evidence documented in release 1.5.0.

On firmware 13.00, service 1.5.1 was activated after confirming there was no
active extraction, compression or transfer. All seven staged package files
were read back and hash-verified in raw SELF mode, with the previous service
retained for rollback. The live flat health response, active rest-mode request
and both original torrents were confirmed after activation. Native screen
acceptance is recorded separately.
